# hybrid_engine 평가 결과 (2026-07)

`evaluation/fidelity.py`(Protocol 1)/`evaluation/cross_camera.py`(Protocol 2)
실측 결과. 재현하려면:

```
python3 -m hybrid_engine.evaluation.fidelity --out eval_reports/fidelity_hasselblad.json
python3 -m hybrid_engine.evaluation.cross_camera --target hasselblad \
    --base-image <아무 인물/풍경 사진> --out eval_reports/generalization_hasselblad.json
```

## Protocol 1: Fidelity (RAW → 공식 렌더러 vs RAW → hybrid_engine)

핫셀블라드 raw+jpeg 13쌍(`raw_calib_cache/`) 전량, `HybridCameraEngine`
기본 profile 기준.

| 지표 | 값 | 해석 |
|---|---|---|
| ΔE00 평균(페어별 평균의 평균) | **15.18** | CIE 기준 "완전히 다른 색"(>10) 구간 |
| ΔE00 P95 평균 | 23.98 | 상위 5% 픽셀은 훨씬 더 나쁨 |
| ΔE00 max 평균 | 58.39 | 페어마다 국소적으로 심하게 틀리는 영역 존재 |
| 그림자(L<33) ΔE00 | 12.52 | |
| 미드톤 ΔE00 | 17.48 | **세 구간 중 가장 나쁨** - 톤커브(블랙/화이트포인트) 문제가 아니라는 신호 |
| 하이라이트(L>66) ΔE00 | 15.97 | |
| SSIM(L채널) 평균 | 0.7409 | 절대 색은 틀려도 대비/구조는 어느 정도 보존(1.0이 완벽 일치) |
| 평균 \|Δhue\| | 34.29도 | 매우 큼 - hue 자체가 크게 어긋남 |

**페어별 편차가 크다**(ΔE00 평균 최저 5.71 ~ 최고 26.79) - 균일한
바이어스가 아니라 장면에 따라 들쭉날쭉하다는 뜻.

### 해석

1. **그림자보다 미드톤이 더 나쁘다는 게 핵심 발견.** 이 프로젝트의
   기존 캘리브레이션 서사(블랙포인트/화이트포인트 맞추기)가 놓치고
   있는 축이 있다는 뜻 - 톤커브를 아무리 정교하게 다듬어도 미드톤
   문제는 못 잡을 가능성이 큼.
2. **Δhue 34도는 매우 크다** - `B1`(학습 LUT)이 톤커브만 손봐서
   ΔE 개선이 미미했던 이유와 정확히 맞아떨어진다. 채도/hue 축이
   병목이라는 진단(README/`hybrid_engine/assets/luts/README.md`에
   이미 기록)이 이 지표로 재확인됨.
3. **SSIM 0.74는 "색은 틀려도 구조는 어느 정도 살아있다"**는 뜻이라
   완전히 무의미한 출력은 아님 - 그러나 절대 색 정확도가 목표라면
   지금 상태로는 부족.

## Protocol 2: Cross-camera generalization (타깃: hasselblad)

소스: fuji(실제 RAW, `raw_calib_cache_fuji/`) + sony/nikon/canon(합성 -
공통 테스트 사진에 `apply_*_look()` 적용, **진짜 카메라 데이터 아님**).

| 소스 | 경로 | 변환 전 b2 | 변환 후 b2 | 변환 전 노이즈σ | 변환 후 노이즈σ |
|---|---|---|---|---|---|
| fuji | 실제 RAW | 42.0 | **58.0** | 1.758 | 2.060 |
| sony | 합성 | 15.0 | 10.0 | 2.253 | 4.408 |
| nikon | 합성 | 19.0 | 10.0 | 2.085 | 4.300 |
| canon | 합성 | 20.0 | 10.0 | 2.043 | 4.334 |

| 요약 지표 | 값 |
|---|---|
| 변환 후 소스 간 b2 표준편차 | 20.78 |
| 변환 후 소스 간 w995 표준편차 | 3.46 |
| 변환 후 소스 간 채도 표준편차 | 23.68 |
| 노이즈 시그니처 소스간 분산(전→후) | 0.178 → 0.991 |
| 지문 소거 비율(post/pre) | **5.57** (1보다 작아야 "소거 성공"인데 오히려 5.57배 커짐) |

### 해석 - 두 가지 실패를 정직하게 인정

1. **합성 소스 3개의 "수렴"(b2 셋 다 정확히 10.0)은 신뢰하면 안 됨.**
   `evaluation/cross_camera.py` docstring에 이미 적어뒀듯, sony/nikon/canon
   합성 소스가 전부 같은 base-image에서 나와서, 브랜드 커브 역산이
   그 브랜드 forward 커브의 거의 정확한 역함수라 다시 같은 사진으로
   되돌아간 뒤 같은 타깃 커브를 맞으니 당연히 수렴한다 - 순환 논증.
   진짜 신호는 **fuji(실제 RAW)가 58.0으로 확 벌어졌다는 것** - 진짜
   다른 카메라/다른 장면이면 전혀 안 수렴한다는 뜻.
2. **지문 소거는 실패했다.** 노이즈 시그니처의 소스 간 분산이 변환
   전(0.178)보다 변환 후(0.991)에 **더 커졌다** - 카메라 고유 렌더링
   특성을 지우기는커녕 오히려 소스 간 차이를 증폭시켰다는 뜻. 다만
   n=4(그것도 3개는 합성)라 통계적으로 약한 신호 - 표본이 더 있어야
   확정적 결론.

## 종합 결론

Protocol 1/2 둘 다 hybrid_engine이 지금 "카메라 렌더링을 정밀하게
재현/일반화한다"는 목표에는 한참 못 미친다는 걸 실측으로 확인했다.
좋은 소식은 병목이 뭔지는 꽤 명확해졌다는 것 - **톤(그림자/하이라이트)
보다 미드톤과 채도/hue 축**. `B1`에서 이미 학습 LUT으로 톤만 손봐서는
개선이 미미했던 것과 이 결과가 일관된다.

**후속 실측(2026-07): 이 문서가 다음 후보로 제안했던 "a/b(채도/hue)
채널 학습 기반 보정"을 실제로 시도했고, 역시 기각됐다.** hue만 따로
학습 LUT으로 보정해도 ΔE 개선은 +2.1%(톤 LUT의 +4.9%보다도 작음) -
자세한 수치와 분석은 `hybrid_engine/assets/luts/README.md` 참고. 톤도
hue도 **개별 축을 1D LUT으로 고치는 접근 자체**가 5% 미만 개선에서
막힌다는 게 이제 두 번 확인됐다는 게 핵심 - "미드톤+hue가 병목"이라는
진단은 맞지만, 그걸 채널별로 독립적으로 고치면 안 풀린다는 뜻이다.
잔차가 L/a/b 결합(joint) 형태일 가능성이 높아서, 다음 후보는 개별
축 LUT이 아니라 **3D 잔차 LUT**이나 Phase 2(공간 연산)다.

**후속 실측 2(2026-07): 3D 잔차 LUT(9^3 격자, L/a/b 결합)도 시도했고,
더 명확하게 기각됐다.** in-sample ΔE는 +11.1%로 지금까지 셋 중 가장
좋아 보였지만, 13-fold leave-one-out 교차검증에서는 **-5.7%(기준선보다
오히려 나빠짐)**로 뒤집혔다 - 729개 격자점을 13장에서 학습하는 건
사실상 암기라 안 본 이미지엔 일반화가 안 된다는 뜻. 자세한 수치는
`hybrid_engine/assets/luts/README.md` 참고. "톤/hue를 각각 고치면
5% 미만"이라는 진단 자체는 여전히 유효하지만, "그러니 조합으로
학습하자"는 지금 표본(13장)으로는 통하지 않는 해법이었다 - 표본이
훨씬 늘어나거나(이슈 #4의 X2D II 데이터), 정규화된 더 성긴 격자로
재시도하기 전까진 Phase 2(공간 연산)나 raw 베이스라인 특성화 쪽이
더 현실적인 다음 후보.

**후속 실측 3(2026-07): "격자가 너무 크면 과적합"이라는 가설을 검증하려고
더 작은 2D 잔차 LUT(a/b만, 81격자)도 시도했다 - 역시 기각.** in-sample
+1.4%, leave-one-out 교차검증 **-2.7%**(729→81로 10분의 1 넘게
줄였는데도 여전히 마이너스). 톤(1D)→hue(1D)→3D(joint)→2D(joint, 더
작은 격자) 네 번의 실험이 전부 기각으로 수렴한 지금, **격자/LUT
계열 접근 자체가 표본 13장 규모에서는 막다른 길**이라고 결론짓는 게
맞다. 자세한 비교표는 `hybrid_engine/assets/luts/README.md` 참고.
다음은 LUT을 더 정교하게 만드는 게 아니라 표본을 늘리거나(이슈 #4)
접근 자체를 바꾸는(Phase 2 공간 연산, raw 베이스라인 특성화) 쪽으로
방향을 틀어야 함.

**후속 실측 4(2026-07): Phase 2(로컬 콘트라스트, L채널 언샤프 마스크)를
시도했다 - 결과는 기각도 채택도 아닌 "무신호(null result)".**
`calibrate_profile.py --mode spatial`이 spatial_radius/amount/threshold
3개를 좌표하강으로 찾았는데:

- 공간 연산 보정 전 ΔE(기준선): 14.85
- 공간 연산 보정 후 ΔE (in-sample): 14.84 (**+0.0%** - 사실상 무보정에 수렴)
- 공간 연산 보정 후 ΔE (4-fold 교차검증): 14.55 (+2.0%)

찾아낸 최적 파라미터 자체가 amount=0.1(탐색 후보 중 최솟값에 가까움)로
수렴했다는 게 핵심 신호 - **좌표하강이 "효과가 거의 없는 게 최선"이라고
판단했다는 뜻.** LUT 실험들과 달리 in-sample보다 교차검증이 더 좋게
나온 것도(+0.0% → +2.0%) 진짜 효과가 아니라 폴드 4개짜리 표본 변동
범위 안의 노이즈로 해석하는 게 맞다 - 실제 효과가 있었다면 in-sample이
교차검증보다 낮게 나올 이유가 없다. **채택 안 함.** 톤/hue/2D/3D LUT
넷의 명확한 음성 결과와 달리 이건 "이 파라미터화로는 신호를 못
찾았다"는 약한 결론이라, Phase 2 자체를 완전히 접기보다는 다른
공간 연산(선명화 반경을 더 세밀하게, 혹은 블루밍/광훈 같은 다른
효과)이나 issue #4의 X2D II 데이터로 표본이 늘어난 뒤 재탐색할
여지는 남겨둔다. `hasselblad.json`은 계속 use_spatial=False로 미변경.

**다섯 번의 실험(톤/hue/3D/2D/공간) 전부가 표본 13장으로는 눈에 띄는
개선을 못 찾았다는 것 자체가 이제 이 프로젝트의 실측 결론이다** - 이
데이터 규모에서 hybrid_engine의 ΔE≈15 병목을 학습 기반으로 뚫는 건
막혀 있고, 남은 현실적인 경로는 (1) 이슈 #4의 X2D II 실측 데이터로
표본을 실질적으로 늘리거나, (2) raw 베이스라인 자체(libraw 렌더링과
Phocus/카메라 엔진의 차이)를 색차트로 특성화해서 지금 측정 중인
"엔진 대 엔진" 차이에서 "raw 디코드 대 raw 디코드" 차이를 분리해내는
것.

원본 JSON 리포트는 이 문서 상단의 두 커맨드로 재현 가능한 산출물이라
커밋하지 않았다(리포지토리에 없음) - 필요하면 위 커맨드를 그대로
실행해서 원하는 경로에 새로 생성하면 된다.
